# Imager 0.20.0

_Released 2026-07-30_

This release adds edit recipes: save what you did to one image, and apply it to another.

## Highlights

- **Save Recipe…**
  Image ▸ Save Recipe… stores the rotation, flips and adjustments made to the current image under
  a name you choose.
- **Apply Recipe.**
  Image ▸ Apply Recipe puts a saved recipe onto the image you are looking at, in one go and as a
  single undo step.
- **Delete Recipe** removes one you no longer want.

## How applying behaves

Applying a recipe **replaces** the orientation and adjustments rather than adding to them, so the
result is the same whatever you had already done.
A recipe holding a 90° rotation gives you a 90° rotation, not 180° on top of a turn you had already
made.

**Any crop you have made is kept.**
Crops are deliberately not part of a recipe: a crop is measured in the pixels of one particular
image, so it cannot transfer to a photo of another size, and in practice it is tone you want to
reuse rather than composition.

## Fixed

- An action that changes nothing no longer costs an undo step.
  Rotating by hand and then applying a recipe that rotated the same way needed ⌘Z twice, because
  the apply landed on the history already in force but still recorded a step.

## Where recipes live

One JSON file each, in Imager's Application Support folder.
Each carries a format version and is read tolerantly, so a recipe saved today will still load after
more adjustments have been added — the ones it never knew about simply read as neutral.

## Under the hood

- Undo and redo now hold snapshots of the edit history rather than individual edits.
  That is what allows applying a recipe to be a single undo step even though it rewrites the
  history, and an edit list is a handful of numbers, so the snapshots cost nothing.
- The test suite is up to 162 tests across 15 suites.

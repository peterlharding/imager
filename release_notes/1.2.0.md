# Imager 1.2.0

_Released 2026-07-31_

This release adds stacks, borrowed from Aperture.

A shoot of four hundred frames is rarely four hundred pictures.
It is a hundred pictures and three hundred alternatives: the burst you fired to catch the moment,
the bracket you took because the light was difficult, the four tries at one composition.
Stacking lets that folder browse as the pictures you actually took, without deleting anything.

## Highlights

- **Group a set into one row.**
  A stack shows a single frame — its *pick* — with a badge saying how many it holds, and a
  disclosure triangle to open it up.
  The frames underneath are always there; they are just out of the way.
- **Stack a whole folder by when the frames were taken.**
  View ▸ Stacks ▸ Stack Photos… groups by capture time.
  The thresholds are named by how the frames were shot — a burst, a bracket, several tries at one
  shot — and the sheet tells you how the folder would group before you commit to it.
- **Choose which frame the set shows.**
  Open a stack, find the one that worked, and Set Pick (⌥⌘P) makes it the frame the stack presents.
  Unstack breaks a group up again.
- **Everything that presents a folder follows the picks.**
  Arrow keys step past a collapsed stack.
  Slideshows show the pictures rather than every frame taken to get them, and Process Folder does
  not spend minutes developing frames you stacked away.

## Where the grouping is kept

In a `.imager` directory beside the photos, holding `stacks.json`.

It records filenames relative to the folder rather than full paths, which is the whole reason for
putting it there: move the folder, rename it, copy it to another disk, and the grouping comes with
it.
Nothing else is written beside your photos, and the file only appears once you stack something.

A folder you cannot write to — a camera card, a read-only mount, a network share — keeps its
groupings in Application Support instead, so they are never silently lost.
Those are keyed by path, so they do not survive the folder moving.

The grouping is checked against the folder every time you open it.
Frames deleted or renamed in Finder drop out, and a stack left with only one frame stops being a
stack.

## One thing worth knowing

Stacking reads the capture time your camera recorded, so it only works on files that carry one.
Scans, screenshots, and anything re-saved by a tool that strips EXIF have no capture time, and
Stack Photos will tell you it found nothing rather than guessing.

Bursts are a special case: EXIF records whole seconds only, so four frames fired in one second all
carry the same timestamp.
Cameras write the fraction separately, and Imager reads it — which is what makes a half-second
threshold mean anything at all.

## Notes

- Move to Trash still takes only what is on screen. Trashing a pick hands the stack to a surviving
  frame; trashing a stack down to one frame dissolves it.
- Expanding and collapsing is a way of looking at a folder rather than a fact about it, so it is
  not remembered between sessions.
- `data/stacks` in the repository holds ten images laid out like a real shoot, for trying this out.
